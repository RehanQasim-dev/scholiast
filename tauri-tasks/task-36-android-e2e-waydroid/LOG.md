
## [2026-08-25] orchestrator — root-caused the "black screen" FORTIFY crash (NOT app code)
- **Symptom:** ~seconds-to-minutes after launch under the waydroid-inspect harness, process SIGABRTs (`FORTIFY: pthread_mutex_lock called on a destroyed mutex`), WebView goes black, a11y tree collapses to an empty WebView shell.
- **Evidence:** crash buffer backtrace (pid 112361, tid `hwuiTask1`): `pthread_cond_wait → HandleUsingDestroyedMutex → libhwui.so android::uirenderer::CommonPool::$_0`. Our Rust/JS frames absent entirely. Crash reproduced once on a scrcpy virtual display (display 7) ~80s into a fresh process with no interaction; NOT reproduced on the default display across multiple boots + a 2-minute soak (alive, zero new crash entries).
- **Diagnosis:** Android 15 (Lineage 22) HWUI CommonPool teardown race triggered by the harness's virtual-display attach/detach around force-stop+relaunch cycles. Framework bug, not reachable from app code. Same category as finding #2 (singleTask multi-display redirect): both are test-harness artifacts, not user-facing defects.
- **Harness rules going forward (SQA briefs must state):** force-stop the app before launching on a DIFFERENT display; treat libhwui CommonPool FORTIFY aborts on secondary displays as S3-environment findings with the backtrace cited, never as app crashes; verify "crash" reports against `-b crash` backtraces before filing S1s.

## [2026-08-25 08:05] orchestrator — CORRECTED root cause: any scrcpy SECONDARY display kills the app; default display immune
- **Correction to previous entry:** not just "mirror churn". Fresh force-stopped launches onto scrcpy virtual displays die at 84s/98s/160s uptime (pids 112361/disp7, 114145/disp9, probe2/disp10) with the identical `libhwui.so CommonPool` destroyed-mutex SIGABRT — even after killing the host-side scrcpy mirror at t=40s (display persists server-side, app still died).
- **Evidence matrix:** default display (`am start` plain): pid 112199 ran for hours; 112819 soaked 2min; 118116 soaked 3m14s — all zero crashes, zero FORTIFY lines. Secondary displays (mirrored OR unmirrored): 3/3 dead within ~1–3min.
- **Backtrace (both crashes):** hwuiTask0/hwuiTask1 → pthread_cond_wait → HandleUsingDestroyedMutex → libhwui.so `android::uirenderer::CommonPool` worker. No app frames ever. Framework composition path specific to Waydroid Lineage-22 secondary displays.
- **Decision:** do NOT set `android:hardwareAccelerated="false"` to dodge it — that would software-render WebView video playback (the core feature) to fix a harness-only defect. SQA verification therefore runs on the DEFAULT display via `force-stop → am start → screencap/uiautomator` (the workflow behind every valid screenshot so far); waydroid-inspect virtual displays are off-limits for this app until the framework bug is fixed upstream.
