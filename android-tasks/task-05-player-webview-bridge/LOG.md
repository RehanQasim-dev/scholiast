  - **Cross-origin capture is the key gotcha**: `player.html` (a `file://` asset) creates the YT iframe on `www.youtube.com` — the `<video>` element inside is cross-origin, so `getIframe().contentWindow.document.querySelector('video')` throws SecurityError by default. The standard WebView workaround (used by many Android YT apps) is `setAllowUniversalAccessFromFileURLs(true)` + `setAllowFileAccessFromFileURLs(true)` on the WebView settings — file:// pages then read cross-origin iframes and the canvas is not tainted. Security tradeoff documented in `PlayerWebView.kt`; flagging for the security review.
  - IFrame API on Android: `playsinline: 1` is mandatory (else the player force-fullscreens), `controls: 0` so only the Compose chrome shows, `fs: 0` to kill YouTube's own fullscreen button, `origin` must be `'file://'` when the host page is a file: URL (a null origin gets "The origin of the player is not authorized").
  - Caption availability is NOT exposed by the public IFrame API; `player.getOption('captions', 'tracklist')` (semi-undocumented) returns the track array — polled a few times after ready/playing since it populates late. `onCaptionsAvailable` is best-effort; Task 12/13 (innertube) is the authoritative source.
  - `@JavascriptInterface` caveat: multiple JS args are comma-joined into ONE string unless quoted, and base64 data URLs are safe from commas but fragile — so every bridge method takes a single String arg; `onCaptureResult` gets a JSON string parsed with `org.json.JSONObject` on the Kotlin side.
